# reports/

Отчёты сверки документации с кодом (`skills/spec-verification`). Каждый прогон — разовый артефакт, а не документ репозитория.

## Что здесь появляется

```text
reports/verification/<YYYY-MM-DD>-<scope>.md             отчёт для человека
reports/verification/<YYYY-MM-DD>-<scope>.evidence.json  машиночитаемые свидетельства
```

`<scope>` — имя feature, `global` или `all`. Коллизия по дате — суффикс `-2`, `-3`; существующий отчёт не перезаписывается.

`.evidence.json` можно передать следующему прогону как baseline: свидетельства перепроверяются против нового commit, устаревшие отбрасываются, поиск не начинается с нуля.

## Правила

- Содержимое `reports/` **не коммитится** (`.gitignore`: `reports/*`, кроме этого README).
- Отчёт не является документом `docs/`: у него нет frontmatter, он не проходит жизненный цикл `draft → approved` и не является source of truth. `scripts/validate-docs.mjs` эту директорию не проверяет.
- Отчёт **фиксирует** расхождения кода и требований, но ничего не исправляет: ни один документ `docs/` и ни один файл `services/` при верификации не изменяется.
- Requirements — правда о требуемом поведении, код — о текущей реализации (`AGENTS.md`, раздел «Source of truth»). Расхождение разрешает человек, а не отчёт.
- Свидетельство `file:line` без зафиксированного commit сервиса невоспроизводимо — снимок кода записывается в секцию Run metadata каждого отчёта.
