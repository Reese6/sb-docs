# Учебные примеры для backend-test-cases

Учебный источник и кейсы ниже — только для проверки скила, не описывают Пульт. Учебные ID и значения не переносить в реальные features.

Что показывает набор: JSON-тело ответа проверяется ровно в объёме гарантий источника — целиком (TC-001), точечно по одному пути (TC-002) или никак, только с `TBD` (TC-003). Проверки статуса без body, когда контракт body задаёт, недостаточно; проверки body, когда контракт его не описывает, — выдумка.

Имя кейса — H1, ID — определение первой строкой тела.

## Учебный источник

```text
Учебный контракт, подтверждённый в рамках тестового задания.
Операция: POST /example/items, JSON-body с единственным полем quantity.
Аутентификация для этой учебной операции не требуется.
quantity — обязательное целое число от 1 до 3 включительно.
Ответы с описанным телом отдаются с Content-Type: application/json.
При допустимом входе ответ: 201, JSON-объект с единственным полем quantity,
равным входному quantity. Состояние и внешние системы не изменяются.
При отсутствии quantity ответ: 422, JSON содержит поле code со значением
QUANTITY_REQUIRED; состав остальных полей этого ответа не гарантирован.
При выходе за диапазон запрос отклоняется; HTTP-статус, media type и body
не описаны.
Окружение: учебный изолированный HTTP-сервис доступен через BASE_URL,
который передаёт тестовый запуск. Подготовка и очистка данных не нужны.
```

## TC-001 — позитивный кейс

```markdown
# Создание учебного item с допустимым quantity

- TC-001 (→ scenario: учебный источник examples.md): POST /example/items
  с допустимым quantity возвращает 201 и JSON с созданным quantity, состояние
  не меняется.

## Цель

Проверить, что POST /example/items с допустимым quantity (границы 1 и 3
включительно) возвращает 201 и JSON-тело с тем же quantity. Уровень проверки —
API-контракт. Приоритет: TBD: шкала приоритетов не предоставлена.

## Источники

Учебный источник examples.md (раздел «Учебный источник»), статус: подтверждён
в рамках тестового задания, версия не указана источником.

## Предусловия

Аутентификация не требуется (учебный источник). Состояние сервиса — без
предварительных записей: операция не читает существующие данные.

## Тестовые данные

| Вариант | quantity | Ожидаемый результат |
|---------|----------|----------------------|
| нижняя граница | 1 | 201, body = `{"quantity": 1}` |
| верхняя граница | 3 | 201, body = `{"quantity": 3}` |

## Подготовка

Not applicable: подготовка данных не нужна (учебный источник).

## Действия

1. Отправить `POST {BASE_URL}/example/items` с заголовком
   `Content-Type: application/json` и телом `{"quantity": <вариант>}`
   для каждого варианта из «Тестовые данные».

## Ожидаемый результат

- HTTP status → equals → `201` → источник: учебный источник.
- Заголовок ответа `Content-Type` → содержит media type → `application/json`
  → источник: учебный источник («Ответы с описанным телом отдаются с
  Content-Type: application/json»).
- JSON body → equals → объект с единственным полем `quantity`, значение равно
  входному `quantity` варианта (для варианта «нижняя граница» —
  `{"quantity": 1}`) → источник: учебный источник. Сравнение объекта целиком
  допустимо: источник гарантирует единственное поле.
- Состояние сервиса и внешние системы → без изменений (источник не описывает
  наблюдаемых эффектов) → источник: учебный источник.

## Очистка

Not applicable: состояние не изменяется (учебный источник).

## Автоматизация

Зависимостей и общего состояния нет; варианты независимы и параллелизуемы.
Изоляция заглушек/часов не требуется.

## Открытые вопросы

Нет открытых вопросов.
```

## TC-002 — негативный кейс

```markdown
# Создание учебного item без quantity

- TC-002 (→ scenario: учебный источник examples.md): POST /example/items
  с body без quantity возвращает 422 и JSON с code QUANTITY_REQUIRED.

## Цель

Проверить, что отсутствие обязательного поля quantity отклоняется с 422 и
точным кодом ошибки в JSON-теле. Уровень проверки — API-контракт. Приоритет:
TBD: шкала приоритетов не предоставлена.

## Источники

Учебный источник examples.md (раздел «Учебный источник»), статус: подтверждён
в рамках тестового задания, версия не указана источником.

## Предусловия

Аутентификация не требуется (учебный источник).

## Тестовые данные

Body: `{}` (поле quantity отсутствует — не `null` и не пустая строка).

## Подготовка

Not applicable: подготовка данных не нужна (учебный источник).

## Действия

1. Отправить `POST {BASE_URL}/example/items` с заголовком
   `Content-Type: application/json` и телом `{}`.

## Ожидаемый результат

- HTTP status → equals → `422` → источник: учебный источник.
- Заголовок ответа `Content-Type` → содержит media type → `application/json`
  → источник: учебный источник.
- JSON body `$.code` → equals → `QUANTITY_REQUIRED` → источник: учебный
  источник.
- JSON body целиком → не сравнивать → источник: учебный источник («состав
  остальных полей этого ответа не гарантирован»); проверяется только путь
  `$.code`.

## Очистка

Not applicable: состояние не изменяется (учебный источник).

## Автоматизация

Зависимостей и общего состояния нет; кейс параллелизуем с TC-001.

## Открытые вопросы

Состав полей ответа 422, кроме `code`, источником не гарантирован — поэтому
проверка точечная (`$.code`), а не сравнение объекта целиком. На подготовку,
действия, ожидаемый результат и очистку это не влияет.
```
