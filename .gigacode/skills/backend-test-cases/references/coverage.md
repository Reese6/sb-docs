# Направления проверок backend тест-кейсов

Перечень для анализа применимости, а не обязательный набор одинаковых кейсов для любого метода. Генерировать конкретную проверку только при наличии основания в источнике.

| Направление | Что рассматривать при наличии соответствующего контракта |
|-------------|--------------------------------------------------------|
| Основной сценарий | Минимальный допустимый вход, полный вход, документированные варианты результата. |
| Валидация | Обязательность, типы, формат, допустимые значения, длины, числовые диапазоны. |
| Границы | Нижняя и верхняя границы и ближайшие значения снаружи; шаг определяется типом и точностью. |
| Сочетания условий | Таблица решений для зависимых полей и бизнес-условий; для независимых данных — представительные классы. |
| Доступ | Без аутентификации, недостаточные права, разрешённая роль, доступ к чужому объекту или области данных. |
| Состояния | Разрешённые и запрещённые переходы, отсутствующая и деактивированная запись. |
| Чтение коллекций | Пустая выдача, фильтры, порядок, равные ключи сортировки, страницы, отсутствие дублей и пропусков. |
| Запись | Сохранение значений, изменение только нужных полей, уникальность, согласованность связанных данных. |
| Повтор и конкуренция | Повторный вызов, идемпотентность, конфликт изменений, конечный инвариант. |
| Ошибки зависимостей | Документированный отказ, тайм-аут, некорректный ответ, восстановление и отсутствие частичных изменений. |
| Асинхронная обработка | Повторная доставка, порядок, повтор обработки, корреляция, завершение или документированный отказ. |
| Время | Граница срока, смена периода, часовой пояс, фиксированное время теста. |
| Наблюдаемые эффекты | Изменения данных, события, аудит, вызовы зависимостей и их отсутствие при отклонении операции. |
| NFR | Измеримые критерии с нагрузкой, длительностью, окружением и методом измерения из источника. |

Недокументированное поведение из этой таблицы записывать как вопрос о применимости, а не ожидаемый результат. Например, требование идемпотентности не следует автоматически из того, что операция использует HTTP.

В негативном кейсе по умолчанию нарушать одно условие, остальные оставлять допустимыми. Сочетания нарушений выделять отдельно, если проверяется документированный приоритет ошибок. Общий список атак или ошибок без связи с контрактом не выдавать за тестовое покрытие.
