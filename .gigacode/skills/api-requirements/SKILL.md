# Skill: api-requirements

## Когда использовать

Создать или изменить `docs/features/<feature>/api/` — контракт клиент–сервер для людей: продакта, тестировщика, разработчиков клиента и сервера. Директория содержит индекс `README.md` и по файлу на каждый метод; один вызов skill — один метод. Источник контракта — `requirements.md`. OpenAPI не генерируется: это отдельная задача по явному запросу. Поводы: готовы `product.md` и `requirements.md`; добавить или изменить API-требование; стадия API оркестратора. Остальные документы — другие skills (AGENTS.md, «Как определить нужный skill»).

## Вход и стоп-условия

| Проверка | Если не выполнено |
|----------|-------------------|
| `product.md` и `requirements.md` feature существуют | Стоп. Ответ: «Сначала product.md (skill `product-documentation`) и requirements.md (skill `requirements`)». |
| Метод и путь названы человеком | Стоп. Составить список методов из `requirements.md`, показать человеку, ждать выбора. Файлы не менять. |
| Документ не `approved`, либо правка MINOR, либо apply утверждённого change proposal | Стоп. Ответ: «Содержательное изменение approved-документа — через `change-management`». |

## Прочитать

1. Обязательно: `product.md` и `requirements.md` feature целиком; `api/README.md` feature, если директория есть; соглашения [docs/api/overview.md](../../../docs/api/overview.md), [conventions.md](../../../docs/api/conventions.md), [authentication.md](../../../docs/api/authentication.md), [errors.md](../../../docs/api/errors.md) — контракт feature обязан им следовать; [roles.md](../../../docs/product/roles.md) — единственный источник ролей; [schemas/README.md](../../../schemas/README.md) — ID и frontmatter. Правила — по AGENTS.md.
2. Если есть: файл правимого метода целиком; `ui.md` и `technical.md` — валидация и ошибки в API обязаны совпадать с UI; документация сервисов [docs/api/services/](../../../docs/api/services/README.md).
3. Остальные файлы `api/` целиком не читать: номер нового ID берётся `grep`-ом (правило 4).

## Правила

Общие — AGENTS.md, `rules/ai-guardrails.md`. Ядро: текст документа, `title` и H1 — русский (заголовки секций — дословно по шаблону; ID, статусы, `TBD`/`ASSUMPTION` — английские); факт — без пометки, только из `requirements.md`, `docs/api/`, документации сервисов или слов человека; неизвестное — `TBD: <что неизвестно>`; предположение — `ASSUMPTION: <текст>. Requires confirmation.`; существующие ID не менять и не переиспользовать.

1. Один метод — один файл `api/<method>-<имя>.md`. За вызов меняется один файл метода и индекс `README.md`; другие файлы не трогать.
2. Имя файла: `<method>` — HTTP-метод строчными, `<имя>` — 1–3 слова kebab-case из glossary или пути (`post-otp-request.md`). Имя занято — уточнить именем ресурса. После создания имя не менять.
3. H1 и `title` файла метода содержат русское название метода: `Запрос кода — POST /v1/otp/request`. Иначе валидатор даёт `MD-H1-LANG`.
4. Новый ID = наибольший `API-XXX` по всем файлам `api/`, включая deprecated, + 1; искать `grep -rn "API-" docs/features/<feature>/api/`. Пропуски не заполнять.
5. Определение требования — первая строка тела файла, строго `- API-007 (→ FR-012): <специфика API>`. Связи нет — найти источник или написать, почему её нет.
6. Изменение формулировки сохраняет ID; удаление метода = `deprecated`, файл остаётся, строка в индексе остаётся.
7. Методы, поля, коды ошибок, лимиты, тайм-ауты, форматы — только из `requirements.md`, `docs/api/` или слов человека, не «по аналогии». Каждый сценарий `product.md`, требующий сервера, проходим через описанные методы; непроходимый — `TBD`.
8. Аутентификация, ошибки, идемпотентность, пагинация, лимиты, форматы — один раз в `docs/api/`; в файле метода ссылка и специфика. Побочные эффекты, события, кэширование — `technical.md`.
9. Специфичный код ошибки — со ссылкой на `docs/api/errors.md`; новый общий код предложить туда, локально не заводить. Роли метода — дословно из `docs/product/roles.md`; нужной роли нет — `TBD` и предложить дополнить `roles.md`.
10. Валидация и семантика ошибок совпадают с `ui.md`; расхождение — пометить конфликт, не «чинить» молча. Документ — проза и таблицы, не YAML-дамп и не OpenAPI.
11. API, которые feature вызывает у чужих систем, — `docs/architecture/integrations.md`; API шире одной feature — `docs/api/services/` через skill `feature-apply`.
12. Новый файл — `type: api`, `status: draft`, `feature: <feature-name>`; правка минимальная. `version`: MINOR без изменения смысла, MAJOR при новых или изменённых API-XXX; `approved` после правки → `review`.

## Шаги

1. Определить метод: из слов человека. Не назван — список методов из `requirements.md`, показать и остановиться.
2. Директории `api/` нет — создать `api/README.md` из [templates/api-index.md](../../../templates/api-index.md).
3. Получить номер: `grep -rn "API-" docs/features/<feature>/api/` → новый ID = наибольший + 1 (правило 4).
4. Создать файл метода из [templates/api-method.md](../../../templates/api-method.md) по правилам 2–3; комментарии `<!-- AI: -->` выполнить и удалить. Файл есть — открыть его.
5. Записать первой строкой определение `- API-XXX (→ FR-XXX): …`, затем заполнить секции Роли, Параметры, Request, Response, Errors; неприменимая — `Not applicable: <причина>`.
6. Обновить `api/README.md`: строка метода в таблице «Методы» и в «Traceability»; затем колонка «Покрыто (UI / API / technical)» в Traceability `requirements.md`.
7. Если изменён существующий `API-XXX`: `grep -rn "API-003" docs/` → проверить расхождение с `requirements.md` и `ui.md` → конфликт пометить `TBD`/`ASSUMPTION` → обновить Traceability затронутых документов.
8. Добавить строку `api/` в таблицу Documents файла `README.md` feature, если её ещё нет.
9. Запустить `node scripts/validate-docs.mjs`; добиться exit 0.

## Примеры

Неправильно — скопирована формулировка BR, выдуманы число и код ошибки:

```text
- API-003: Пользователь может запросить код повторно не чаще одного раза в 60 секунд, при более частом вызове endpoint возвращает 429 с кодом RATE_LIMIT_EXCEEDED.
```

Правильно — только ID источника и специфика API; неподтверждённый код — TBD:

```text
- API-003 (→ BR-002): повторный вызов ранее истечения интервала повторной отправки возвращает 429. TBD: код ошибки — по docs/api/errors.md.
```

## Чеклист

- [ ] Изменён ровно один файл метода плюс `api/README.md`; имя файла по правилу 2, H1 с русским названием.
- [ ] Определение `- API-XXX (→ FR-XXX): …` — первой строкой тела; номер не переиспользован.
- [ ] В файле метода есть все секции шаблона или `Not applicable: <причина>`.
- [ ] Строка метода есть в таблицах «Методы» и «Traceability» индекса; колонка «Покрыто» в `requirements.md` обновлена.
- [ ] Роли — только идентификаторы из `roles.md`; отсутствующая помечена `TBD`.
- [ ] Ни формулировки FR/BR/NFR, ни глобальные соглашения не скопированы — только ID, ссылки и специфика метода.
- [ ] Ни одного выдуманного метода, поля, кода или лимита; каждый `ASSUMPTION` — с `Requires confirmation.`
- [ ] Документ человекочитаем; в OpenAPI не превращён.
