# Правила документации

Как писать документы: источники фактов, ID, статусы, ссылки, отчёт.

## Источники и факты

- Полные правила — `rules/`: `ai-guardrails.md`, `writing.md`, `requirements.md`, `linking.md`, `terminology.md`, `markdown.md`. `rules/ai-guardrails.md` читать перед любой правкой.
- Факт — только из source of truth (`AGENTS.md`, раздел «Source of truth») или слов человека.
- Неизвестное — `TBD: <что неизвестно>`. Предположение — `ASSUMPTION: <текст>. Requires confirmation.`
- Требования, API, бизнес-правила, лимиты, форматы не придумывать.

## ID и статусы

- Существующие ID не менять и не переиспользовать. Удалённое требование — `deprecated`.
- Новый документ — `status: draft`. `approved` не ставить: его выставляет только человек.
- Изменённый `approved`-документ переводить в `status: review`.
- Содержательное изменение `approved`-документа — только через skill `change-management`.

## Связи и стиль

- Термины — только из `docs/product/glossary.md`.
- Ссылки — относительные. Глобальный контекст не копировать — ссылаться по ID.
- После правки требования — проверить связанные UI/API/technical, обновить Traceability.

## Отчёт

- В конце работы — отчёт по шаблону skill: файлы, ASSUMPTION, TBD, следующий шаг.
