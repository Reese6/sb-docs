# Команда /feature-model

Выполни skill `.gigacode/skills/data-model/SKILL.md` целиком: прочитай файл и пройди его секции по порядку — «Вход и стоп-условия», «Прочитать», «Правила», «Шаги», «Чеклист».

Аргументы: {{args}}

Первое слово аргументов — имя feature в kebab-case. Второе слово — имя сущности, например `otp-code`.
Имя feature не указано или директории `docs/features/<feature-name>/` нет — остановись и ответь: «Укажи имя feature: /feature-model <feature-name> <entity>».
Имя сущности не указано — составь список сущностей из требований `requirements.md` с пометкой «существующая / новая / изменение», покажи его человеку и остановись до подтверждения. Файлы при этом не менять.
Имя сущности указано — создай или заполни ровно один файл `docs/features/<feature-name>/model/<entity>.md` и обнови индекс `model/README.md`; остальные файлы не трогать. Сущность используется без изменений — файла не создавать, добавить только строку-ссылку в индекс.

Отчёт — по секции «Отчёт» из SKILL.md; последнюю строку замени на «Следующая команда: /feature-model <feature-name> <entity>» для следующей сущности из списка, а когда сущности кончились — «Следующая команда: /feature-ui <feature-name>» при наличии интерфейса, иначе «Следующая команда: /feature-api <feature-name>».
