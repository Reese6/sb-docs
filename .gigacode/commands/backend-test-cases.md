# Команда /backend-test-cases

Выполни skill `.gigacode/skills/backend-test-cases/SKILL.md` целиком: прочитай файл и пройди его секции по порядку — «Вход и стоп-условия», «Прочитать», «Правила», «Шаги», «Чеклист».

Аргументы: {{args}}

Первое слово аргументов — имя feature в kebab-case.
Имя не указано или директории `docs/features/<feature-name>/` нет — остановись и ответь: «Укажи имя feature: /backend-test-cases <feature-name> <METHOD> <path> | scenario <name>».
Второе слово — HTTP-метод (например `POST`) или литерал `scenario`. Второй случай: третье слово — имя сценария в kebab-case, остальное — уточнения человека.
Первый случай: третье слово — путь метода; вместе они определяют один файл `api/<method>-<имя>.md` как источник контракта.
Ни метод, ни `scenario` не указаны — составь список операций и сценариев из `requirements.md` и `api/`, покажи его человеку и остановись до подтверждения. Файлы при этом не менять.
Метод/путь или сценарий указаны — создай или обнови ровно один файл `tmp/test-cases/<feature-name>/tc-<NNN>-<имя>.md` и обнови индекс `tmp/test-cases/<feature-name>/README.md`; остальные файлы не трогать.

Отчёт — по секции «Отчёт» из SKILL.md; последнюю строку замени на «Следующая команда: /backend-test-cases <feature-name> <METHOD> <path>» для следующей операции из очереди, а когда очередь пуста — «Следующая команда: /feature-review <feature-name>».
