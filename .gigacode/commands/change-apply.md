# Команда /change-apply

Выполни skill `.gigacode/skills/change-management/SKILL.md` целиком: прочитай файл и пройди его секции по порядку — «Вход и стоп-условия», «Прочитать», «Правила», «Шаги», «Чеклист». Режим — по body `## Status` файла `proposal.md`: `approved` — «Режим apply», `rejected` — «Режим rejected», `proposed` — стоп по таблице «Вход и стоп-условия».

Аргументы: {{args}}

Первое слово аргументов — имя изменения в kebab-case, остальное — уточнение человека.
Имя не указано или директории `docs/changes/<change-name>/` нет — остановись и ответь: «Укажи имя изменения: /change-apply <change-name>; активные — список в docs/changes/README.md».
Статусы `approved` и `rejected` не выставлять ни у proposal, ни у целевых документов — только читать.

Отчёт — по секции «Отчёт» из SKILL.md, режим apply; для rejected — строки «Файлы:» с путём архива и «Статус: rejected — архивирован». Последнюю строку замени на «Следующая команда: при находках review — команда документа с находкой, например /feature-requirements <feature-name>; иначе перевод целевых документов в approved — решение человека», для rejected — «Следующая команда: нет — proposal архивирован».
