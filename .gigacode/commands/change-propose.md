# Команда /change-propose

Выполни skill `.gigacode/skills/change-management/SKILL.md` в режиме propose: прочитай файл и пройди его секции по порядку — «Вход и стоп-условия», «Прочитать», «Правила», «Шаги» (только «Режим propose»), «Чеклист».

Аргументы: {{args}}

Первое слово аргументов — имя изменения в kebab-case, остальное — что изменить и в каком документе.
Имя не указано или не kebab-case — предложи 2–3 варианта имени по запросу и остановись до выбора человека.
Директория `docs/changes/<change-name>/` уже существует — остановись и ответь: «Proposal <change-name> существует — решение человека в `## Status`, затем /change-apply <change-name>».
Целевой документ не назван и из запроса не выводится — спроси одним списком, не больше пяти вопросов, и остановись. Файлы при этом не создавать.
Создавать только `docs/changes/<change-name>/` и строку в «Активные изменения» `docs/changes/README.md`; целевые документы и другие proposal не менять.

Отчёт — по секции «Отчёт» из SKILL.md, режим propose; последнюю строку замени на «Следующая команда: после решения человека в `## Status` — /change-apply <change-name>».
