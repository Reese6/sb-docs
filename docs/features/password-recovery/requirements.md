# Password recovery — requirements

## Context

Формализация сценариев восстановления пароля из [product.md](product.md): запрос восстановления по email, подтверждение OTP, установка нового пароля, повторная отправка кода.

## Functional Requirements

- FR-001: Неаутентифицированный пользователь может запросить восстановление пароля, указав email учётной записи.
- FR-002: Система должна отправить OTP на указанный email, если учётная запись с таким email существует.
- FR-003: Пользователь может подтвердить владение учётной записью, введя действующий OTP.
- FR-004: Пользователь должен установить новый пароль после успешного подтверждения OTP, чтобы завершить восстановление.
- FR-005: Пользователь может запросить повторную отправку OTP после истечения интервала повторной отправки (BR-002).

## Business Rules

- BR-001: Пользователь может иметь только одну активную сессию восстановления пароля. Rationale: исключает одновременное действие нескольких OTP для одной учётной записи.
- BR-002: Повторная отправка OTP допускается только после истечения интервала повторной отправки. Rationale: ограничивает злоупотребление отправкой кодов. TBD: длительность интервала повторной отправки.
- BR-003: После превышения допустимого числа неверных вводов OTP сессия восстановления завершается, код становится недействительным. Rationale: защита от перебора кода.
- BR-004: Процесс восстановления не должен раскрывать, существует ли учётная запись с указанным email. Rationale: защита от перечисления пользователей.

Глобальные business rules не определены — см. [../../product/business-rules.md](../../product/business-rules.md).

## Non-functional Requirements

- NFR-001: OTP доставляется пользователю после запроса в пределах целевого времени. ASSUMPTION: не более 60 секунд для 95 % запросов.
  Requires confirmation.
- NFR-002: OTP хранится на сервере только в необратимом виде; открытое значение кода не попадает в логи и постоянные хранилища.

Глобальные NFR не определены — см. [../../product/non-functional-requirements.md](../../product/non-functional-requirements.md).

## Acceptance Criteria

- AC для FR-001, FR-002: Given учётная запись с email `user@example.com` существует, When пользователь запрашивает восстановление с этим email, Then создаётся сессия восстановления и на email отправляется OTP.
- AC для BR-004: Given учётной записи с email `unknown@example.com` не существует, When пользователь запрашивает восстановление с этим email, Then ответ системы неотличим от ответа для существующего email и OTP не отправляется.
- AC для FR-003: Given активная сессия восстановления и действующий OTP, When пользователь вводит этот OTP, Then система подтверждает владение учётной записью и разрешает установку нового пароля.
- AC для BR-003: Given пользователь исчерпал допустимое число неверных вводов OTP, When он вводит любой код ещё раз, Then ввод отклоняется и сессия восстановления завершена.
- AC для FR-004: Given подтверждённый OTP, When пользователь задаёт новый пароль, удовлетворяющий политике паролей, Then пароль учётной записи обновлён и сессия восстановления завершена.
- AC для FR-005, BR-002: Given активная сессия восстановления и истёкший интервал повторной отправки, When пользователь запрашивает повторную отправку, Then на email отправляется новый OTP.
