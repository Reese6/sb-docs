# Password recovery — product

## Problem

Пользователь, забывший пароль, теряет доступ к учётной записи. Самостоятельного пути восстановления нет: единственный способ вернуть доступ — обращение в поддержку.

## Goal

Пользователь самостоятельно восстанавливает доступ к учётной записи без обращения в поддержку, подтвердив владение учётной записью.

## User scenarios

- Пользователь забыл пароль. Он запрашивает восстановление, указав email, получает одноразовый код (OTP, см. [glossary](../../product/glossary.md)), вводит его, задаёт новый пароль и входит в систему.
- Пользователь не получил OTP и запрашивает повторную отправку кода.
- Негативный сценарий: пользователь исчерпал допустимое число попыток ввода OTP и вынужден начать восстановление заново.

## Expected behaviour

- После запроса восстановления пользователь видит одно и то же подтверждение независимо от того, существует ли учётная запись с указанным email.
- После ввода действующего OTP пользователь получает возможность задать новый пароль.
- После установки нового пароля пользователь может войти с ним; восстановление на этом завершено.

## Business value

Снижение количества обращений в поддержку и возврат пользователей, потерявших доступ.

## Scope

- Восстановление пароля по email с подтверждением OTP.
- Повторная отправка OTP.
- Ограничение числа неверных попыток ввода OTP.

## Out of scope

- Восстановление по SMS.
- Восстановление через обращение в поддержку.
- Смена пароля аутентифицированным пользователем из профиля.
- Блокировка учётной записи при подозрительной активности.

## Dependencies

- Наличие у учётной записи email.
- ASSUMPTION: у каждой учётной записи есть подтверждённый email.
