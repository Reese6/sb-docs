# 03. Глобальные правила AI (rules/)

> Источник: INIT.md, ЭТАП 4. Приоритет: P0 («Rules» идёт до «Metadata/IDs» по разделу «Порядок приоритетов»).
> Зависит от: 02.

## Цель

Создать каталог `rules/` с глобальными правилами для AI-агентов. Особое внимание — `ai-guardrails.md`.

## Шаги

1. Создать `rules/ai-guardrails.md` — центральный документ защиты от галлюцинаций.
2. Создать остальные правила:
   - `rules/writing.md`
   - `rules/requirements.md`
   - `rules/terminology.md`
   - `rules/markdown.md`
   - `rules/linking.md`

## Требования к ai-guardrails.md

Зафиксировать принцип трёх категорий информации:

```text
FACT
ASSUMPTION
TBD
```

AI запрещено превращать предположение в факт. Assumption не должен автоматически становиться утверждённым требованием.

Если информация неизвестна:

```text
TBD: время жизни OTP-кода.
```

или:

```text
ASSUMPTION: срок жизни OTP составляет 5 минут.
Requires confirmation.
```

## Обязательные правила

- не придумывать требования;
- не придумывать API;
- не придумывать бизнес-правила;
- не придумывать ограничения;
- не дублировать одно требование между несколькими файлами;
- использовать cross-reference;
- сохранять существующие requirement IDs;
- перед изменением документа анализировать связанные документы;
- при изменении требования искать связанные UI/API/technical требования;
- использовать единый glossary;
- избегать AI-стиля и чрезмерно абстрактных формулировок;
- писать документацию простым профессиональным языком;
- разделять WHAT/WHY и HOW.

## Результат (deliverables)

- `rules/ai-guardrails.md`
- `rules/writing.md`
- `rules/requirements.md`
- `rules/terminology.md`
- `rules/markdown.md`
- `rules/linking.md`

## Критерии готовности

- Принцип FACT/ASSUMPTION/TBD зафиксирован с примерами.
- Все 13 обязательных правил распределены по файлам без дублирования.
- Правила написаны так, чтобы AI мог их стабильно соблюдать.
