# 10. Skill `technical-documentation`

> Источник: INIT.md, ЭТАП 10. Приоритет: P1.
> Зависит от: 08, 09.

## Цель

Создать `skills/technical-documentation/SKILL.md` — skill для разработчиков, описывающий HOW.

## Поведение skill

Перед созданием технической спецификации:

1. Прочитать product documentation.
2. Прочитать requirements.
3. Прочитать UI/API specification.
4. Проверить `services/`.
5. Если исходный код доступен — изучить соответствующие сервисы.
6. Найти существующие архитектурные решения (ADR).
7. Только после этого описывать техническое решение.

Выход: `technical.md` по `templates/technical.md`.

## Ключевой принцип

```text
requirements = source of truth для требуемого поведения

services source code = source of truth для текущей реализации
```

Не путать эти два понятия. Если код противоречит утверждённому требованию — явно отметить расхождение (не исправлять автоматически в пользу кода).

## Результат (deliverables)

- `skills/technical-documentation/SKILL.md`

## Критерии готовности

- Все 7 подготовительных шагов зафиксированы как обязательные.
- Принцип двух source of truth включён дословно.
- Правило явной отметки расхождения кода и требований описано.
