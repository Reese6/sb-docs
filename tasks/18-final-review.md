# 18. Финальная проверка

> Источник: INIT.md, ЭТАП 18. Приоритет: P4. Завершающая задача.
> Зависит от: 17.

## Цель

Провести end-to-end проверку всего проекта и исправить найденные проблемы.

## Шаги

1. Вывести дерево директорий.
2. Проверить каждый `SKILL.md`.
3. Проверить, что между skills нет противоречий.
4. Проверить `AGENTS.md`.
5. Проверить templates.
6. Запустить локальную validation (`scripts/validate-docs.*`).
7. Проверить demonstration feature.
8. Проверить cross-reference.
9. Найти дублирование правил.
10. Исправить найденные проблемы.

## Сценарий-проверка

```text
Пользователь:
"Добавь возможность восстановления пароля по SMS"
```

Описать, как `documentation-orchestrator` должен обработать запрос:

```text
product context
→ product
→ requirements
→ ui
→ api
→ technical
→ review
```

## Критерий качества проекта

Новый AI-агент, ничего не знающий о проекте, после чтения только `AGENTS.md` и `README.md` может самостоятельно понять:

- структуру документации;
- где искать информацию;
- что является source of truth;
- какой skill применять;
- какие файлы создавать;
- какие файлы изменять;
- как связывать требования;
- как работать с неизвестной информацией;
- как проверить результат.

## Критерии готовности

- Все 10 шагов проверки выполнены, проблемы исправлены.
- Сценарий SMS-recovery разобран по pipeline.
- Финальный отчёт выведен в заданном формате.
- Проект готов к использованию командой через Claude Code / Codex CLI.
