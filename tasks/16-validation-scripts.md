# 16. Автоматические проверки

> Источник: INIT.md, ЭТАП 17. Приоритет: P4 (по разделу «Порядок приоритетов» validators идут до external skills).
> Зависит от: 15 (нужна example feature для проверки валидатора).

## Цель

Создать простые локальные проверки документации. Не строить тяжёлую платформу.

## Минимум проверок

- broken relative Markdown links;
- duplicate requirement IDs;
- malformed IDs;
- отсутствующий YAML frontmatter там, где он обязателен;
- неизвестные document types;
- ссылки на несуществующие FR/UI/API/ADR ID;
- базовая Markdown-структура.

## Шаги

1. Выбрать минимальный и переносимый стек (без тяжёлых dependencies).
2. Создать `scripts/`, например:

   ```text
   scripts/validate-docs.*
   ```

3. Прогнать валидацию по всему репозиторию, включая example feature.
4. Добавить команду запуска проверки в `README.md`.

## Ограничения

- Не добавлять тяжёлые dependencies без необходимости.
- Схемы из `schemas/` — источник правил для проверки frontmatter.

## Результат (deliverables)

- `scripts/validate-docs.*`
- Обновлённый `README.md` с командой запуска.

## Критерии готовности

- Все 7 проверок реализованы.
- Валидация проходит на текущем состоянии репозитория (или все найденные проблемы исправлены).
- Команда запуска задокументирована в README.md.
