# Markdown rules

Правила структуры Markdown-файлов.

## Frontmatter

- YAML frontmatter обязателен для документов в `docs/` (кроме README.md директорий) и для документов features.
- Формат и обязательные поля — `schemas/README.md` и `schemas/metadata.schema.yaml`.
- Frontmatter — первый блок файла, между `---`.
- `title` — на русском языке; латиница допустима для ID (`ADR-001`), аббревиатур (API, UI, OTP) и терминов glossary, зафиксированных на английском. Валидатор требует хотя бы одну букву кириллицы (`schemas/metadata.schema.yaml`).

## Заголовки

- Один `#` (H1) на файл, на русском языке, совпадает с `title` из frontmatter. Язык заголовков секций (H2 и ниже) задаёт шаблон или существующий файл, а не автор ([writing.md](writing.md)).
- Иерархия без пропусков: `##` → `###`, не `##` → `####`.
- Для feature-документов заголовки секций — из соответствующего шаблона `templates/`; порядок секций шаблона сохраняется. Для глобальных документов (`docs/product/`, `docs/api/`, `docs/architecture/`) шаблонов нет — сохраняется существующая структура файла.
- Пустые секции не удаляются молча: либо содержимое, либо `TBD: ...`, либо явное «Not applicable: <причина>».

## Кодовые блоки

- Всегда с указанием языка: ` ```yaml `, ` ```json `, ` ```text `.
- Примеры request/response, ID, диаграммы-псевдографика — в кодовых блоках, не в прозаическом тексте.
- Диаграммы — Mermaid в блоке ` ```mermaid `, где диаграмма полезна.

## Списки и таблицы

- Маркированные списки — `-` (не `*`).
- Таблицы — только для сопоставимых данных с короткими ячейками; длинные объяснения — прозаическим текстом.

## Файлы

- Имена файлов и директорий — kebab-case, латиница.
- Кодировка UTF-8, перевод строки LF, файл заканчивается переводом строки.
- Один документ = один файл; не склеивать несколько типов документации (product + technical) в одном файле.
