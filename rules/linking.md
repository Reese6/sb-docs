# Linking rules

Правила ссылок и cross-reference. Цель — traceability без дублирования.

## Не дублировать — ссылаться

**Одно требование живёт ровно в одном файле.** Все остальные документы ссылаются на него по ID.

- Глобальные правила продукта не копируются в feature — feature ссылается на `docs/product/` (см. `docs/features/README.md`).
- Формулировка требования не повторяется в ui/api/technical — там только ID и специфика уровня.
- Найденный дубликат — ошибка review: оставить одну формулировку, остальные заменить ссылками.

Неправильно (в `ui.md`): «Пользователь может запросить код повторно не чаще одного раза в 60 секунд, кнопка "Отправить снова" заблокирована 60 секунд».
Правильно: «UI-005: кнопка "Отправить снова" заблокирована до истечения интервала повтора (BR-002)».

## Cross-reference по ID

Связь уровней документации выражается ссылками ID → ID:

```text
UI-004 → FR-012     UI-требование реализует функциональное требование
API-007 → FR-012    API-требование реализует то же FR
ADR-003 → NFR-002   архитектурное решение обосновано NFR
```

- Направление ссылки: от производного к источнику (UI/API/technical → FR/BR/NFR; ADR → требования).
- Каждое существенное UI/API-требование ссылается минимум на один FR/BR/NFR; висячие требования находит review.
- Сводная traceability — в секции `Traceability` документа (в `model/README.md` — «Трассируемость»); формат — в шаблонах `templates/`.

## Markdown-ссылки

- Только относительные пути (пример из `docs/features/<feature-name>/`: `../../product/glossary.md`), не абсолютные и не URL репозитория.
- Ссылка на секцию — через якорь: `requirements.md#functional-requirements`.
- Первое упоминание ID из другого файла сопровождается ссылкой на файл; повторные — допустимы голым ID.
- Битая ссылка — ошибка review; автоматически проверяется `scripts/validate-docs.mjs`.

## Перед изменением — анализ связей

При изменении требования:

1. Найти все документы, ссылающиеся на его ID (grep по `FR-XXX` и т.п.).
2. Определить, какие связанные UI/API/technical требования затронуты.
3. Обновить их или явно пометить конфликт (`TBD`/`ASSUMPTION` — по `ai-guardrails.md`).
4. Обновить секции `Traceability`.
