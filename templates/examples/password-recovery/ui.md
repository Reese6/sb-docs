# Восстановление пароля — UI

## Purpose

Поведение интерфейса восстановления пароля: запрос кода, ввод OTP, установка нового пароля.

## Related requirements

FR-001, FR-003, FR-004, FR-005, BR-002, BR-003, BR-004, BR-005 — см. [requirements.md](requirements.md).

## Entry points

- UI-001 (→ FR-001, BR-004): ссылка «Забыли пароль?» на экране входа ведёт на экран запроса восстановления.

## Screens

Дизайн-макеты отсутствуют. TBD: ссылка на задачу дизайна.

### Экран запроса восстановления

Поле email и кнопка отправки запроса. После отправки — экран ввода кода с нейтральным сообщением «Если учётная запись существует, код отправлен» (→ BR-004).

### Экран ввода кода

- UI-002 (→ FR-003, BR-005): поле ввода OTP и кнопка подтверждения; просроченный код отклоняется (BR-005).
- UI-004 (→ FR-005, BR-002): кнопка «Отправить снова» заблокирована до истечения интервала повторной отправки; рядом отображается оставшееся время. Отсчёт ведёт клиент от значения интервала BR-002 (`TBD: длительность интервала`); сервер оставшееся время не сообщает (см. [api.md](api.md), API-004, BR-004).

### Экран нового пароля

- UI-003 (→ FR-004): поле нового пароля, поле повтора пароля, кнопка сохранения. После сохранения — переход на экран входа.

## Components

- Форма email (экран запроса).
- Поле ввода OTP и кнопка «Отправить снова» (экран ввода кода).
- Форма нового пароля (экран нового пароля).

Дизайн-система отсутствует — новые компоненты не изобретаются, используются стандартные элементы форм. TBD: дизайн-система.

## Component states

- Кнопки отправки (все экраны): default / disabled (форма невалидна или запрос выполняется) / loading.
- Кнопка «Отправить снова»: disabled до истечения интервала (→ BR-002), default после.
- Поле OTP: default / error (неверный или просроченный код, BR-005).

Остальные состояния (hover, focus и другие): Not applicable: без дизайн-системы не специфицируются.

## Actions

- Отправка формы email → запрос API-001, переход на экран ввода кода (UI-001).
- Ввод OTP и подтверждение → запрос API-002; при успехе — переход на экран нового пароля (UI-002).
- Клик «Отправить снова» → запрос API-004 (UI-004).
- Сохранение нового пароля → запрос API-003; при успехе — переход на экран входа (UI-003).

API-ссылки — см. [api.md](api.md).

## Validation

- Email: проверка формата при submit; при ошибке — сообщение у поля.
- OTP: поле не может быть пустым при submit. TBD: длина и алфавит OTP (см. Open Questions в requirements.md) — до уточнения формат не проверяется на клиенте.
- Новый пароль: совпадение полей пароля и повтора при submit. TBD: политика паролей — клиентская проверка сложности не специфицирована.

## Loading states

Во время запроса кнопка отправки формы блокируется и показывает индикатор выполнения; повторная отправка формы недоступна.

## Empty states

Not applicable: в сценарии нет списков и загружаемых данных.

## Error states

- Ошибка сети или сервера: сообщение с возможностью повторить действие.
- Неверный или просроченный OTP (BR-005): единое сообщение у поля кода без уточнения причины (API возвращает неразличимую ошибку — BR-004); поле остаётся доступным.
- UI-005 (→ BR-003): после исчерпания допустимого числа попыток — сообщение о завершении сессии восстановления и переход на экран запроса восстановления.

Семантика ошибок — из [api.md](api.md) и [../../api/errors.md](../../api/errors.md).

## Navigation

- «Назад» с экрана ввода кода возвращает на экран запроса. ASSUMPTION: активная сессия восстановления при этом не завершается.
  Requires confirmation.
- Прямой выход из сценария возможен на любом шаге; вернуться можно только с начала (запрос кода).
