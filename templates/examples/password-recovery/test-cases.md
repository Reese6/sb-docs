## Test Cases

### TC-001: Запрос восстановления пароля с существующим email

| Поле | Значение |
|------|----------|
| Приоритет | Высокий |
| Требования | FR-001, FR-002, UI-001, API-001, AC для FR-001, FR-002 |
| Предусловия | Учётная запись с email `user@example.com` существует; пользователь не аутентифицирован |

**Шаги:**

1. На экране входа перейти по ссылке «Забыли пароль?» (UI-001).
2. Ввести email `user@example.com`.
3. Отправить форму запроса восстановления.

**Ожидаемый результат:** Открыт экран ввода кода с нейтральным сообщением «Если учётная запись существует, код отправлен»; на `user@example.com` отправлен OTP; создана сессия восстановления.

### TC-002: Запрос восстановления с несуществующим email неотличим от успешного

| Поле | Значение |
|------|----------|
| Приоритет | Высокий |
| Требования | BR-004, API-005, AC для BR-004 |
| Предусловия | Учётной записи с email `unknown@example.com` не существует |

**Шаги:**

1. Открыть экран запроса восстановления.
2. Ввести email `unknown@example.com`.

**Ожидаемый результат:** Ответ и экран неотличимы от случая существующего email (то же нейтральное сообщение); OTP не отправлен; факт отсутствия учётной записи не раскрыт.

## Not covered by manual testing

- NFR-001 — доставка OTP за целевое время для 95 % запросов: статистическая цель, требует измерений на объёме запросов.
- NFR-002 — необратимое хранение OTP и отсутствие кода в логах: требует доступа к серверному хранилищу и логам.
- API-003 / Idempotency — повторное использование `reset_token`: не воспроизводится через интерфейс, требует API-инструмента.
- API-005 — неотличимость по времени ответа для существующего и несуществующего email: требует инструментального измерения.
