# ADR-001: Одноразовый код вместо ссылки восстановления

## Status

proposed

## Context

Для восстановления пароля нужен механизм подтверждения владения учётной записью через email. Два распространённых подхода: одноразовый код (OTP), который пользователь вводит в интерфейсе, и ссылка восстановления, открываемая из письма. Требования: FR-002, FR-003, NFR-002 (см. [../requirements.md](../requirements.md)).

## Decision

Мы будем использовать одноразовый код (OTP), который пользователь вводит на экране подтверждения.

## Alternatives

- Ссылка восстановления (recovery link) в письме. Плюсы: один клик вместо ввода кода; не нужен экран ввода. Минусы: сценарий привязан к устройству, на котором открыто письмо; переход по ссылке зависит от поведения почтового клиента; состояние между письмом и приложением передаётся через URL. Отклонена: сценарий с вводом кода работает одинаково на любом устройстве и упрощает мобильный поток.

## Consequences

- Плюсы: пользователь может получить код на одном устройстве и ввести на другом; единый поток для web и мобильных клиентов.
- Минусы: нужен экран ввода кода и защита от перебора — ограничение попыток (BR-003) и rate limits.
- Нейтральное: код хранится только в виде хэша (NFR-002); нужен интервал повторной отправки (BR-002).
