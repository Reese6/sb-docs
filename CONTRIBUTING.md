# CONTRIBUTING

Правила внесения изменений в документацию. Применяются и к людям, и к AI-агентам.

## Общий процесс

1. Определить затрагиваемую feature или глобальный раздел.
2. Прочитать связанные документы (product, requirements, ui, api, technical этой feature).
3. Внести изменения по шаблонам из `templates/` и правилам из `rules/`.
4. Обновить cross-reference и traceability.
5. Прогнать проверку (skill `documentation-review` и `node scripts/validate-docs.mjs`).
6. Закоммитить с осмысленным сообщением.

Эти шаги в виде сценариев для человека, работающего с AI-агентом (промпты, точки контроля, итерации), — [WORKFLOW.md](WORKFLOW.md).

## Правило минимального изменения

При изменении существующей документации:

1. Найти связанные документы.
2. Определить impact.
3. Изменять только необходимые части.
4. Не переписывать документ целиком без необходимости.
5. Сохранять ID требований.
6. Обновлять cross-reference.
7. Запускать review.

## Изменение утверждённых документов

Содержательное изменение документа со статусом `approved` — добавление, изменение или удаление требований (MAJOR-версия) — вносится только через change proposal в `docs/changes/<change-name>/` (процесс — skill `.gigacode/skills/change-management`, структура — `docs/changes/README.md`):

- MINOR-правки approved-документов (опечатки, ссылки, формулировки без изменения смысла) и любые правки `draft`/`review`-документов — обычный процесс, без proposal.
- Жизненный цикл proposal: `proposed → approved → applied` (или `rejected`); `approved`/`rejected` выставляет только человек.
- После apply целевые документы получают MAJOR bump версии и переходят в `review`; proposal архивируется в `docs/changes/archive/YYYY-MM-<change-name>/`.

## Статусы документов

```text
draft → review → approved → deprecated
```

- Новый документ создаётся в статусе `draft`.
- Перевод в `approved` — только человеком (product owner / lead), не AI.
- Устаревший документ помечается `deprecated`, а не удаляется.

## Требования и ID

- Формат и жизненный цикл ID — `schemas/README.md`.
- ID стабильны: изменение текста требования не меняет его ID.
- Удалённые ID не переиспользуются.
- Одно требование живёт в одном файле; остальные документы ссылаются на него.

## Неизвестная информация

- Неизвестный факт: `TBD: <что неизвестно>`.
- Предположение: `ASSUMPTION: <предположение>. Requires confirmation.`
- Придумывать требования, API, бизнес-правила и ограничения запрещено (`rules/ai-guardrails.md`).

## Стиль

- Простой профессиональный язык, без «AI-стиля» и абстрактных формулировок (`rules/writing.md`).
- Терминология — строго по `docs/product/glossary.md` (`rules/terminology.md`).
- Markdown-структура — по `rules/markdown.md`, ссылки — по `rules/linking.md`.

## Коммиты

- Один логический блок изменений = один коммит.
- Сообщение описывает, что изменилось и в какой feature: `docs(password-recovery): add FR-007..FR-009 for SMS flow`.
